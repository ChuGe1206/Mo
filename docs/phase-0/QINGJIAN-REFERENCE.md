# 青简参考边界（2026-09-28）

参考源：[qingjian-team/qingjian README](https://github.com/qingjian-team/qingjian)。这是产品与架构比较，不引入其代码或资源。

青简公开强调输入优先、平台无关核心与系统输入接口分层、本地处理和不干扰输入的辅助候选信息。Mo 已采用 Rust 核心加 Windows TSF 薄壳、离线 librime 引擎和独立 Broker；目前应继续把可安装性、输入正确性、首次切换及尾延迟放在功能扩展之前。候选注释、学习辅助与可选本地增强可作为后续体验方向，但必须在真实宿主和性能门通过后再接入逐键路径。

可操作的顺序：

1. 在可销毁 Windows 11 x64 VM 中执行开发测试包的安装、修复、升级、卸载和真实 Notepad/WinUI 输入矩阵，取得 `ACCEPTANCE.md` 的 G2/G3 证据。
2. 完成默认包的逐文件许可证结论、对应源、签名链和首次使用性能证据，满足 G3/G4。
3. 在真实宿主验证设置即时生效、候选显示及多屏 DPI，再评估注释、学习与可选辅助信息；新增处理不得上传输入内容或记录敏感文本。

青简仓库以 GPL-3.0-or-later 发布；Mo 自有代码采用 Apache-2.0。参考行为和交互原则，独立实现，不复制青简代码、素材或受限标识。
