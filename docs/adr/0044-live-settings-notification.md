# ADR 0044：设置保存后通知已运行的 Windows TIP

## 状态

已实现并通过本机非注册探针；真实桌面宿主与安装后的权限边界仍待 VM 验收。

## 背景

ADR 0041–0043 已让普通用户安全保存候选窗主题，也让 Broker 与 TIP 在连接时读取
版本化设置快照。但保存时已连接的 TIP 不会主动查询，用户必须切换焦点或等待重连。
设置通知还必须避开 50 ms 按键路径，且不能把外部通知内容当作可信设置。

## 决策

1. 设置中心仅在原子保存或明确恢复默认设置成功后，使用注册的 Windows 消息
   `Mo.Settings.Changed.v1` 向当前桌面的顶层窗口发送无 payload 的失效提示。发送失败不
   撤销已落盘的设置，界面将成功保存和通知失败分别告知用户。
2. 每个已激活的 TIP 实例在所属线程上持有一个不显示、不激活的顶层接收窗口。
   接收器随 `ActivateEx` 创建、`Deactivate` 销毁；创建失败不阻止 TSF 激活。
   通知不会触发 Broker 启动或新建连接。
3. 已连接的 TIP 在窗口消息路径上调用现有 `GetSettings` 协议，从已认证的 Broker
   查询 18 字节快照。只有 revision 变化时才以当前候选快照重绘候选窗。设置文件读取
   与 IPC 均不进入逐键热路径。没有连接的 TIP 下次连接时照常读取最新设置。
4. 旧 Broker 没有协商设置 feature 时保留当前输入会话和默认主题。Broker 对运行中
   损坏文件返回稳定的 `ERROR_SETTINGS_UNAVAILABLE` 时，TIP 保留当前会话、候选窗
   与最后有效主题，等待修复后的下一次通知。传输歧义、非法回复或超时才断开会话并
   清理自身未提交的预编辑，防止新会话与旧预编辑混用。
5. Windows 消息只是提示，不携带设置值、路径或授权信息。接收器只接受 Broker 的
   强类型快照；设置格式和 IPC 帧格式均未变化。通知可因窗口创建失败、进程权限、
   桌面隔离或消息投递失败而缺失，此时下次连接仍会加载已保存的设置。

## 验证

- x64 与 Win32 MSVC `/W4 /WX` 构建、COM 加载及非注册通知窗口探针通过。探针覆盖
  同线程两个接收器、广播分别到达、先销毁一个接收器后另一个仍可接收，以及最终
  接收器销毁。受控 fake/真实词库 TSF 探针还在 `OnTestKeyDown` 和 `OnKeyDown` 之间投递
  一次通知，随后核对按键只提交一次；既有 IPC probe 继续核对 `GetSettings` 的真实
  Broker 往返。
- Rust workspace 测试、格式和 all-targets Clippy 通过；原子保存、损坏恢复与 Broker
  最后有效快照仍由设置核心测试覆盖。
- 全新离线 stage 保留 84 份 Mo 源码、132 份安装 payload、139 份 stage 文件；manifest
  SHA-256 为 `61D2F7FC486B4792D5A2E6D90FF58C03C427D269918D5AE6EE4608DAFBE32960`。
  88 项 staging、20 项 WiX 作者层检查、7 组机器词库 golden 和 x64/Win32 各 10 轮
  受控崩溃恢复（合计 40 次明确 Broker 退出）通过。
- WiX 4.0.6 链接并反向验证未执行的 `0.0.7.0` ProductionShape：MSI SHA-256
  `F972112FB5E7FAED379583B8C059F54EBF8EA689B08126ACF0436DE4EC30AAA6`，Bundle SHA-256
  `2A99FA30577E10B1DAC0323AA1050CA15EBBA84C57F706A3F2A84D6BE50C6699`。
  12 项合规、8 项来源材料及 7 项签名顺序测试通过；MSI ICE 和实际签名未执行。
- 此阶段未启动设置 GUI，也未在系统中安装、注册或启用输入法。普通 Notepad/WinUI
  的实时重绘，以及普通用户设置中心向提升权限宿主发消息的行为仍需隔离 VM 验收。
