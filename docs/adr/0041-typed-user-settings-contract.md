# ADR 0041：普通用户设置采用强类型、版本化、非执行配置

## 状态

已接受并实现设置模型、编解码和原子存储；尚未接入图形设置前端、Broker 或
librime option/schema 激活。

## 背景

Mo 面向不知道 Rime、schema、部署和 YAML 的普通用户。ADR 0039 又明确安装态
Lua、schema 与 deployed data 只能来自受审计的机器目录。因此设置中心不能通过
向 `LocalAppData\Mo\Rime` 写 `.custom.yaml` 或 Lua 来改变运行时；那既重新打开了
覆盖边界，也会把实现细节暴露给用户。

设置文件还必须区分“不存在”“损坏”和“来自未来版本”。把任何解析错误静默降级
为默认值会造成用户选择丢失，并可能在旧版本启动时覆盖新版本字段。

## 决策

1. 新增纯产品层 crate `mo-settings`。安装路径固定为由
   `FOLDERID_LocalAppData` 推导的 `Mo\Profile\settings-v1.mo`，与 Rime 用户词典
   和学习数据库分开。
2. v1 是最大 16 KiB 的规范 UTF-8 文档，包含固定 header、`format=1` 和精确的
   强类型字段：输入方案、简繁、候选页大小、注释、Emoji、本地学习、隐私模式、
   主题。编码顺序确定，不包含 YAML、Lua、模块路径或任意键值扩展。
3. 未知、缺失、重复、错误类型、越界候选数、非法 UTF-8 和嵌入回车全部拒绝。
   未来 `format` 返回“不支持版本”；只有文件确实不存在时才使用产品默认值。
4. 默认值为全拼、简体、5 个候选、显示注释、Emoji 开启、本地学习开启、隐私
   模式关闭和跟随系统主题。隐私模式只让“有效学习”变为 false，不抹掉用户原有
   学习偏好。
5. 保存先在同目录以 `create_new` 创建唯一临时文件，写入并 `sync_all`，随后在
   Windows 用 `MoveFileExW(REPLACE_EXISTING | WRITE_THROUGH)` 原子替换。失败清理
   自己创建的临时文件，不覆盖目录、符号链接或其他非普通目标。
6. 本阶段不声称这些设置已经影响真实输入。librime 后端继续拒绝未经 ABI/真实
   词库验证的 schema/option 操作；设置 UI、应用协议和数据槽生成器分别验收。

## 验证证据

- 14 项单元测试覆盖全部枚举往返、规范编码、乱序/CRLF 读取、默认值、隐私模式
  派生语义、候选范围、非法 UTF-8、超限、未知/缺失/重复字段、未来版本、损坏文件、
  文件缺失、首次保存、原子覆盖、临时名碰撞及非普通目标拒绝。
- Windows 实际执行了首次写入和覆盖测试，并确认目录中没有遗留 Mo 临时文件。
- crate 不引入新的第三方包；只复用 workspace 已锁定的 `windows-sys 0.61.2`。

## 后果与后续

普通设置现在有独立、稳定且不可执行的数据边界，后续 UI 不需要理解 Rime 文件。
未来格式升级必须显式增加迁移器，不能让旧解码器吞掉新字段。

下一阶段需要定义 `Settings -> validated runtime plan`：仅把当前实际支持的选项应用到
Engine session；需要生成 schema 的设置进入新的签名/哈希绑定机器数据槽，不能写入
用户 staging。完成设置前端、跨进程刷新、迁移/回滚和真实输入验证之前，本 ADR 不把
设置功能标记为用户可用。
