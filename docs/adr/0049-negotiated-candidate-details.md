# ADR 0049：协商候选注释与选择标签

## 背景与决策

librime 已向引擎提供候选文字、注释和选择标签，但 Broker 原有 `Snapshot` 只传文字，TIP 候选窗只能显示固定序号，设置中的 `show_comments` 也没有可见效果。

IPC 1.0 新增 `FEATURE_CANDIDATE_DETAILS` 和 kind 15 `DetailedSnapshot`。双方都协商该位且客户端允许至少 34260 字节 payload 时，Broker 才返回带每个候选可选注释、可选标签的快照；否则继续返回原 kind 6 `Snapshot`，不改变其字节布局。注释限 256 UTF-8 字节，标签限 32 字节；单项元数据超限时只省略该项，不丢弃已处理的按键或候选页授权。解码仍严格拒绝截断、尾随字节和无效 UTF-8。

TIP 优先显示引擎标签；没有标签时使用本页序号。设置中心新增“显示候选注释”复选框，连同已开放的方案、简繁和主题原子保存。设置变更广播只作为重新读取提示；TIP 从已认证 Broker 获取新设置后重绘当前候选窗。关闭注释仅影响显示，候选选择仍使用 revision 和零基索引授权。

## 验证与剩余边界

- Rust 编解码测试覆盖带注释/标签的往返、截断/尾随拒绝和旧快照不变；Broker 测试覆盖完整协商、未协商及 payload 预算不足时的回退。
- x64/Win32 原生探针验证协商和标签投影；fake 与真实 librime/rime-ice 的 IPC、候选窗、鼠标选词及故障恢复冒烟测试通过。设置中心控制器测试验证关闭注释与其他选项同文档保存。
- 自绘 GDI 候选窗仍未实现 TSF UIElement 协作；真实注册宿主中切换复选框并观察即时重绘仍待隔离 VM 验收。
