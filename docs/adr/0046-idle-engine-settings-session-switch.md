# ADR 0046：空闲边界自动切换引擎设置会话

## 状态

已实现并通过隔离探针；真实注册宿主中的设置操作、尾延迟和可安装发行仍待 VM 验收。

## 背景与决策

ADR 0045 将输入方案与简繁模式应用于新建 librime 会话，但保存设置后，已经连接的 TIP 不会自行新建会话。用户必须切换焦点或重启宿主，和一键安装、少设置的目标不符。

TIP 收到跨进程通知后，仍只向已认证的 Broker 查询设置；通知本身不承载可信设置。主题继续即时重绘。若方案或简繁与当前会话不同，TIP 标记待切换，在下列条件同时成立时替换会话：当前 `OnTestKey*`/`OnKey*` 配对已经结束、没有由 TIP 持有的预编辑范围、不是 TSF 终止回调、Broker 连接仍有效。提交或清空预编辑的 edit session 结束后，隐藏通知窗口给自己投递一次消息，使替换发生在编辑锁之外，也不占用逐键 IPC 时限。鼠标选择候选后的路径采用相同边界；失焦会关闭旧会话，再次聚焦自然读取新设置。

客户端在同一认证连接中先发送 `OpenSession`，拿到不同的新 token 后才发送 `CloseSession` 退休旧 token。新增协商位 `FEATURE_SESSION_SETTINGS_ACK`：支持它的 Broker 在 `OpenSessionAck` 中返回本次创建会话所用的精确 18 字节设置快照；TIP 以此更新已生效方案和简繁，避免 `GetSettings` 与 `OpenSession` 之间发生保存时误记旧配置。未协商时应答继续为空。Broker 对设置不可用或创建失败的稳定拒绝不会删除旧会话；任何传输、帧或关闭结果不明确的情况直接断开整条连接，避免猜测 token 或重放已可能提交的键。成功切换后丢弃旧候选页身份和显示快照。设置文件格式不变。

设置中心文案相应改为“当前输入完成后自动切换”。这不是迁移当前预编辑，也不是实时逐键改写 librime 状态；旧 Broker 混用不受支持。

## 验证与剩余边界

- Rust Broker 回归覆盖：旧会话存在时设置文件损坏或后端拒绝创建新会话，`OpenSession` 稳定拒绝后旧 token 的预编辑仍可继续；修复或重试后先打开新 token、再关闭旧 token，新会话从空预编辑开始，应答精确返回小鹤双拼与繁体快照。未协商该位的旧应答保持空载荷。
- C++ IPC 探针覆盖同连接的新旧 token、generation 与设置 revision；隐藏窗口探针覆盖延后通知投递和停止后拒绝投递。x64/Win32 `/W4 /WX` 构建、独立 TSF 生命周期、真实 librime/rime-ice IPC/16 客户端池/候选窗/鼠标/故障恢复探针通过。
- 当前源码已重建 development stage，并通过机器数据七组 golden、真实引擎候选探针及 stage 双架构 Broker 崩溃恢复；未签名 ProductionShape MSI/Bundle 仅完成链接和结构反向核验，未执行安装。
- 未在开发主机注册或安装 Mo，也未打开设置 GUI 操作真实用户配置。通知恰落在 TSF 测试键与实际键之间的场景由现有隔离探针验证同一键只分发一次；真实设置变化与真实注册宿主联动仍需隔离 VM 验收。首次使用与候选窗尾延迟没有因此宣称达标。
