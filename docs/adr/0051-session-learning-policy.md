# ADR 0051：按会话暂停本地学习

## 背景与决策

设置文件已有 `local_learning` 和 `privacy_mode`，有效学习状态定义为前者为真且后者为假。此前两项仅展示，librime 仍会写用户词典。设置中心现在允许修改两项；“隐私模式”明确标为“暂停学习”，不暗示清除已有词典、禁止所有磁盘访问或保护密码输入框。

Broker 为每个新会话传入 `mo_disable_learning = !effective_learning`。锁定的 librime core Memory 与合并的 Lua Memory 的提交、删词及显式更新入口在该选项为真时拒绝写入。运行时构建将两个源码补丁和 SHA-256 纳入 provenance，staging 验证要求与当前源码完全绑定。TIP 只在有效学习状态改变时沿 ADR 0046 的空闲边界替换会话；用户在未提交的预编辑中修改设置，旧会话完成后才生效。

## 验证与边界

- 对旧运行时的负控证明单传该选项仍会学习。新运行时通过同一独立用户目录的私密 → 正常 → 私密会话测试，导出的 `rime_ice.userdb` 条数与频次分别为 0、1、1。
- Rust 测试覆盖四种学习/隐私组合的会话选项、设置原子保存及允许列表；真实资源 smoke 同时检查 actor 接受该选项。
- 最终源码已重新生成 ProductionShape 与 DevelopmentTest 两份 132-file stage；`0.0.9.7` 的生产形态包及 `0.0.9.7 → 0.0.9.8` 开发升级对通过链接反向核验和 MSI ICE。clean/matrix VM kit、SPDX 草案、9 份源码归档、15 份通知材料及签名顺序计划均按新哈希生成并核验；未运行安装或签名。
- staged x64/Win32 后续各连续 10 轮故障恢复通过，共 40 次明确 Broker 退出；此前复验仍在 x64 第 2 轮出现一次 47 ms 首键未消费，不能据成功重跑宣称偶发问题已修复。带轨迹的 x64 对照 10 轮、740 次按键全部通过，单次最高 13.429 ms；非轨迹开发布局 x64 10 轮也通过，差异尚未定位。轨迹脚本原先固定请求号导致假失败，已改为按键消息类型统计。
- 2026-09-29 进一步追踪：同一用户目录复用后，固定布局的首次 `N` 仍在 `RimeBackend::apply` 的原生 `process_key` 中耗时 95.329 ms，TIP 等待响应头 57.645 ms 后按 50 ms deadline fail-open。仓库布局的另一轮首个 `N` 仅 1.460 ms，但后续 `H` 的 `process_key` 51.229 ms、候选上下文读取另约 34.4 ms，也超时。直接 librime 对照曾出现首键 290.674 ms 与第三键 117.248 ms，随后九个新进程首键为 1.229–1.600 ms。复用用户目录、更换 DLL 路径和布局均不能稳定消除峰值；诊断计时代码已撤回，未改变生产 50 ms 预算或重发策略。原生调用延迟的触发条件仍未查明。
- 另一轮固定布局在第四个键出现 `process_key` 墙钟 55.433 ms、Windows 线程 CPU 时间增量 0 µs；线程 CPU 计时粒度有限，只能提示等待/抢占可能性，不能据此认定磁盘 I/O 或锁争用。该轮也只在临时调试构建启用 CPU 追踪，正式源码和 stage 未包含该计时。
- 该策略针对锁定的 rime-ice 数据和这些受控写入入口。运行时仍需读取已有用户词典；不可将此选项宣传成“无痕模式”或对任意第三方 Lua 脚本的隔离保证。
- 已安装 VM 中的设置交互、跨进程会话切换、升级回滚和签名仍须按安装测试清单验收；首键偶发未消费须继续调查。
